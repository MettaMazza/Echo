# Shared browser HTTP integration

This is candidate implementation with live browser evidence, not a deployed group interface. The production archive remains schema 10. A separately seeded schema-20 archive and isolated server are used for acceptance. The server source now accepts archive versions through 20; it does not migrate production automatically.

All endpoints use the existing bearer-device authentication and exact Origin/Host checks. Browser-created groups use the fixed `browser` / `local` namespace; the channel identifier equals the group identifier. Request data cannot select Discord or another connector's namespace. Membership grants no administrator role.

| Endpoint | Request | Behavior |
|---|---|---|
| `/api/group-create` | `group` | Create an idempotent group owned by the authenticated principal. |
| `/api/groups` | Empty object | List only this principal's joined groups and invitations, with current revision and caller principal. Joined members see the current joined/invited roster; invitees receive no roster. |
| `/api/group-change` | `group`, `operation`, `member`, `state`, `previous` | Apply an exact-retry membership change against the current revision. An invitation does not grant access; the invited principal accepts their own join. Creator removal and self-departure retain immutable history. |
| `/api/group-state` | `group` | Read current membership revision and eligible historical segments with latest run IDs, under one snapshot. It never creates or changes a segment. |
| `/api/group-open` | `group` | Resolve/create the segment for the current audience and report its latest run. |
| `/api/group-submit` | `group`, `submission`, `message`, optional `attachments`, optional `session` | Bind sender, selected sources and current audience; claim and launch the normal isolated worker. The UI supplies its selected session, so membership changes reject a prepared draft rather than silently rerouting it. |

The existing session, status, progress, trace and compaction routes admit authenticated recorded group members. Read transactions keep the audience check and returned text in one database snapshot. Attachment routes use the independently tested group scope. Private ownership checks remain separate; branch/revise/export behavior is not implicitly widened by this change.

Only the exact initiating device may claim, retry or cancel a shared run. Being the creator or another member does not grant control over that run. The frozen initiating authority still governs every tool call. Privileged history cannot be repeated after the audience's authority changes.

A ready run with a saved cancellation request and no worker claim now becomes cancelled without starting inference. Running workers retain their normal cancellation monitor; this path does not declare an active process stopped.

Browser transcripts now expose immutable recorded_sender metadata for shared user messages; the renderer displays the recorded principal as literal text. Private messages retain the You label and Echo replies retain Echo. Native tests cover spoofed text, principal relinking and private-history compatibility; an actual browser fixture covers sender labels and literal markup. The candidate sidebar now creates groups, lists invitations, accepts/declines them, lists members, invites by principal ID, removes members as creator, leaves and opens current shared segments. Group selection is persisted separately from private conversations; saved submissions select the original group endpoint and retain their session. Native tests and an actual two-principal browser/model exchange pass. The status response exposes can_control; another member can observe without receiving Stop or Retry controls. Private-only branch/edit/export/speech controls are withheld for group sessions until shared semantics are implemented. The selected group now observes read-only state every 1.5 seconds (a UI refresh cadence, not an inference deadline), discovers new runs and displays eligible historical segments. Old segments disable submission and attachment upload. Membership changes never move a draft or selected segment; access removal clears the displayed transcript while retaining an unsent draft. Late responses are ignored after navigation. Native scope tests and a real browser/model exchange verify this behavior. Unresolved submissions can now be preserved in Saved submissions to unlock other chats, with explicit original-ID checking and no audience change; see SAVED-SUBMISSIONS.md for evidence and limits. Shared-media/revision semantics remain unfinished. Discord delivery, shared export/revision semantics, repeated group compaction and physical-device acceptance remain separate requirements.

## Publishing shared workspace files

The candidate attach_file dispatcher now resolves the device and arguments from the exact running tool-call receipt. A shared workspace file can be copied into immutable attachment storage and shown under the reply to its eligible audience. Registration rechecks the frozen call authority inside the same writer transaction as the attachment event, as well as current membership and history eligibility. A later role grant cannot revive the old call. Legacy private publication remains supported and passed its existing regression.

Native tests cover actual queued dispatch, exact bytes, both members/outsider checks, changed authority before registration, departure and reopen. An actual primary-model turn published shared.ep; the isolated browser displayed it beneath Echo’s reply, opened its original text, and downloaded bytes matching the archived SHA-256. Evidence: evidence/phase2/group-publication-verification.json. This qualifies attach_file publication; direct shared Speak-button jobs are described after the model-requested media jobs below.


## Shared model-requested media

`app/media/shared_authority.ep` resolves the authenticated device from the exact running tool ledger call and its frozen authority. Speech synthesis, transcription and image generation require the original run, current membership revision, eligible history and unchanged authority. Media arguments cannot choose the caller. Speech and image executors reject each other’s call families. The existing helper monitor repeats these checks during execution.

Shared audio transcription resolves only originals in that shared session, through the caller’s current audience eligibility. Private transcription retains its existing branch/ancestor lookup. Generated WAV, PNG, transcript and timing attachments use the exact-call publication transaction, which rechecks authority after staging and before registration. Denied/uncertain publication retains the helper diagnostics and staged original; it does not authorize blind replay.

Tests: `tests/media/test_group_voice_tool.ep` exercises real local Kokoro synthesis and local recognition through scripted model calls, both-member access, outsider exclusion, text provenance and replay refusal. `tests/media/test_group_image_tool.ep` exercises the real local image engine through the same dispatcher. `tests/security/test_group_media_authority.ep` checks each media family, wrong-device publication and an authority change while ordinary group membership remains writable. Private voice and direct Speak authority regressions are also run. Results and archive receipts are in `evidence/phase2/shared-media-verification.json`.

This is candidate integration. Direct shared Speak-button jobs now have their own authenticated initiating-job receipt, described below. Model-chosen shared generation, membership-change-during-helper acceptance and production rollout remain separate checks.

## Direct shared Speak button

Candidate migration21 adds immutable `echo_group_speech_jobs` origins. An authenticated current member can speak a saved reply without a new model turn or invented user message. Tool capture freezes the clicking device/principal and authority epochs; exact call/source/text matching limits the receipt to speech synthesis. The media monitor and guarded publication check current membership, derived-history eligibility, original authority and node emergency epochs. Model, image and admin capabilities cannot be obtained from this direct-job receipt.

The job identity binds the original reply, clicking device and authority epochs. Same-authority repeated clicks reuse the saved audio; a fresh click after an authority change is a new request. Different members may initiate separate jobs, each with their own receipt. Old membership segments remain readable but cannot create new speech jobs. The UI exposes Speak on the current shared segment; the resulting player and download persist with the original reply.

Native tests passed real Kokoro generation, repeat idempotence, member/outsider/departure access, forged-text rejection, role-change invalidation and rejection of image/admin reuse. Private direct speech and shared model-media authority regressions passed. An isolated schema21 browser showed Speak, generated one WAV from two clicks, played it (readyState4; 2.944 seconds), restored it after reopening and downloaded bytes matching its archived SHA-256. The source reply was a scripted completed model turn from a different member. Fixture credentials were revoked and its server stopped. Evidence: `evidence/phase2/direct-shared-speech-verification.json`. Production is still schema10; this is candidate acceptance, not rollout.
