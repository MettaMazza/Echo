# Procedural memory — Step 09

The ErnosDecent reference (`decent_store/knowledge.ep`, procedure_store/get/list) retains named workflow text. Echo's procedure versions retain that authored workflow plus the original observed tool calls, expected outcomes, exact discovery contracts and runtime build identity required by Phase Two.

`app/memory/procedures.ep` stores immutable `procedure_version` events in the existing archive. A manifest has a name, purpose, prerequisites, ordered steps and failure lessons. Each step names a tool and its contract hash, original result event/digest and preceding discovery event/digest, plus expected JSON values at paths under the original `$.result`. Exact retry identities are idempotent. New identities retain new versions rather than rewriting earlier evidence. No separate mutable database or migration is introduced.

A proposed workflow has empty execution references. A demonstrated workflow requires all steps to have observed tool-ledger results in order in one execution run, exact original digests, preceding tool discovery in that run, matching contracts and matching declared output checks. This proves the recorded checks, not an unrestricted claim of mastery or independently verified external success. Source scopes remain private or bound to the exact shared audience revision, using the existing project scope rules.

Read/search rechecks source access and tool dependencies. Tool contracts now include the deployment's `ECHO_RUNTIME_BUILD_SHA256`, derived from the server/helper executable hashes; UI-only changes are excluded. Changed code or contracts yield `stale-tool`. Missing build identity prevents qualification. A stored workflow never executes automatically and never grants authority. Each real invocation still passes ordinary authorization.

`procedure` exposes save, read and paginated search. `tool_search` supplies the contract hash and a scoped saved-procedure match alongside builtin discovery; further versions can be traversed using procedure search. This makes existing workflows visible during discover-before-create selection. Prerequisites and failure lessons remain authored descriptions; successful execution is established only by linked observations and declared checks.

## Forgetting and restoration

The visibility extension appends `procedure_visibility` events rather than deleting workflow or execution evidence. `procedure set_visibility` requires the current visibility revision, requested state and reason. Repeated identical calls are idempotent; stale revisions and foreign scopes are rejected. Reads of forgotten versions return only status/revision, while search and tool discovery omit them. Explicit restoration appends a new transition and ordinary read-time dependency/source checks still apply.

Saving identical manifest bytes in the same scope resolves to the existing version, so a fresh tool-call identity cannot resurrect a forgotten copy. The production audit before this extension found zero procedure versions and zero duplicate groups. The native lifecycle fixture reached forgetting, restart, duplicate prevention and restoration before a duplicate fixture credential stopped foreign-user setup; that setup was corrected. The corrected native regression passed for forgetting/restart, exact-content deduplication, stale and foreign changes, explicit restoration and intact chains. The actual local model resumed and executed the workflow; streamed visibility tools then hid it from real tool discovery and explicitly restored it. Deployed as `phase2-procedure-lifecycle-20261017-003954`; local and LAN endpoints returned 200, runtime build fingerprint was verified, and the model stayed running. Evidence is in `evidence/phase2/procedure-lifecycle-20261017/`. No new physical-phone acceptance is claimed.

An independent database snapshot/restoration regression also passed: a workflow forgotten before backup remains hidden from reads and discovery in the restored copy, with intact archive chains. The original copy still permits explicit restoration and rejects stale or foreign changes. Evidence: `evidence/phase2/memory-recovery-20261017/forgotten-*`.
