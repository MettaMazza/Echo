# Conversation work panel

Implemented within Step 10. `app/web/work_status.ep` provides a read-only, cursor-paged snapshot for conversation runs and schedules. The authenticated device is checked as active; selected conversation access and each returned run are checked separately, with linked-device ownership resolution. Direct delegated children are candidates only if their own current read access succeeds. Schedule definitions remain scoped to their originating conversation. No tool execution, cancellation, schedule mutation or worker launch occurs in this reader.

`tests/web/test_work_status.ep` passed current run state, exact cursor exhaustion, empty schedule results, foreign-device isolation, cancellation refresh, revoked-device denial and source archive integrity. The first fixture lacked the normal cancellation schema and was corrected; its failed database is preserved separately. Evidence: `evidence/phase2/work-panel-20261017/reader-result.json`.

The authenticated `/api/work` endpoint and Work sidebar button are now deployed. The dialog has runs/schedules selection, user-selected batch size, cursor paging, Refresh, last-check time and collapsed record details. It performs no job control. Real browser checks loaded 20 then 40 records without replacement and switched between runs and empty schedules. HTTP checks passed valid paging, invalid amount rejection, inaccessible-session denial and unauthenticated denial. `tests/web/test_work_lineage.ep` additionally passed populated schedule instruction/due-time retrieval, foreign schedule exclusion, private and shared direct-child visibility, exclusion of private children from shared views, nonmember denial and access revocation after group departure. No workers were launched. Two existing absent-event diagnostics preceded its zero-exit PASS. Together these results cover the read-only conversation work panel; they do not close Step 10, later live HUDs or final physical-device/endurance acceptance.
