## Invocation and data flow

`web_fetch` takes exactly one URL. `web_search` takes a query and encodes its UTF-8 bytes for DuckDuckGo’s HTML search. `web_follow` takes an extracted document attachment and a numbered link; it resolves that link from a digest-verified source in the current conversation’s attachment scope. Navigation records the source event, exact digest, link index and target URL before fetching. The dispatcher rereads the immutable call and requires current frozen user authority and write access to its private or shared conversation. Model arguments cannot select storage, programs, headers, credentials, proxies or a different principal. The schema is advertised only when host configuration supplies `ECHO_RESEARCH_RUNTIME` and `ECHO_RESEARCH_ROOT`. The runtime directory contains the compiled `fetch_public` helper; the storage root is private and outside user-writable workspaces.

Each call gets a storage directory derived from archive identity, run and call. Files are exclusive creations. A separate helper performs native curl requests; the supervisor retains dispatch, cancellation and exit evidence. No shell, browser login, host cookie jar or curl configuration is used. The helper receives a clean environment. Proxy use and netrc are disabled explicitly; TLS peer and hostname verification stay enabled. It exits if its launching parent disappears.

URL parsing uses the installed curl URL API. Only HTTP and HTTPS are accepted. Credentials, IPv6 zones and control characters are refused. Resolution uses the installed Darwin resolver. Every returned address must pass binary public-address classification, including special-purpose ranges from the saved IANA snapshot. Approved DNS addresses are pinned with CURLOPT_RESOLVE; literal IPv6 is validated directly and requires no DNS. Each hop has a new handle, preventing inherited cookies, authentication and connection state. Redirects are followed manually through the same parsing and resolution checks; repeated normalized URLs stop as a cycle. There is no application redirect-count, response-size or elapsed-time quota.

The helper writes and flushes every hop's request, response body, headers and result. Its final receipt contains requested and redirect URLs, approved addresses, actual connected peer, HTTP status, curl error and content type. HTTP errors retain their originals and receive `http-error`; a successful TCP/TLS transfer is not treated as a successful HTTP page. A refused redirect preserves earlier completed hops.

After reaping, the dispatcher rechecks authority and publishes each original body and headers through the existing scoped attachment transaction. It records a `web_fetch_receipt` and returns attachment identities, complete-byte SHA256 values and citation URLs. UTF-8 originals can be read using `attachment_read_text`. HTML responses also receive an independent `libxml2-static-html` document attachment containing title, derived text and every numbered anchor with its original href and normalized HTTP(S) target. Script/style/template text is excluded; HTML entities and declared base URLs are handled by the native parser. HTTP charset declarations are passed to the parser. The original remains authoritative; derived text is not a byte-identical substitute. Parsing runs in the same cancellable helper and does not execute scripts or fetch page resources. Known DuckDuckGo challenge/no-result markers and recognized result counts distinguish search success from an unavailable or challenged page. No challenge bypass is attempted. Original bodies now retain the normalized declared MIME type; headers remain text/plain. Unknown or malformed MIME values become application/octet-stream. Declared PDFs therefore use the existing digest-verified page extractor, and supported images retain their image types for the existing image tools. A declaration does not validate the file contents: invalid/locked/no-text PDFs retain their existing explicit error statuses. Server content is untrusted data, not an instruction source.

## Failure and recovery

Cancellation or authority change terminates the helper; the supervisor waits for the owned process. Cancellation is distinct from download completion. Request records and any partial files remain in the private call directory. Partial files are not silently published as complete sources. The result points to the dispatch receipt and existing output reader. A persistence failure retains an unresolved tool claim instead of manufacturing success. A new request must not overwrite an earlier call's originals.

A process crash can leave staged files without publication. Their operator recovery is through the recorded call directory and request/transfer receipts; an automatic partial-source browsing tool is not implemented. This is a known unfinished recovery surface within step 08, not a new numbered task. DNS and transfer work are isolated in the helper, so parent cancellation can terminate either phase.
