# Group memory — Step 09, integration in progress

`app/memory/group_knowledge.ep` provides native audience-scoped semantic and episodic storage, graph traversal and explicit visibility transitions. The common knowledge and visibility entry points now route shared runs to this backend, preserving the private path. Chronological queries now also route through the common timeline entry point. Automatic context now selects current, unexpired, visible claims from earlier objectives and rechecks their source authority. This group-recall stage is deployed.

Claims are immutable `group_memory_claim` archive events, with deterministic identities covering the exact audience, source event/digest, assertion, evidence class, dates and correction reference. They do not enter any participant's private memory tables. Source access requires the initiating run's current group authority and permitted source history. A private source cannot be imported through this path. Model-authored source records retain inference status; tool-observation status requires an actual tool-result or process-output source kind.

Corrections preserve the earlier claim and allow only one successor for the same audience, kind, subject and predicate. Forgetting/restoration uses immutable `group_memory_visibility` events with expected-revision checks and exact retry identities. Graph traversal hides forgotten content; management lookup returns visibility state and revision. Audience changes invalidate the old initiating run and do not expose old claims to the new audience. Original records remain available in the archive under their own permissions.
