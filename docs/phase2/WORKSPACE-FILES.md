# Scoped workspace file tools

Step 08 file tooling continues the existing read, create and mkdir operations. `workspace_list` adds directory enumeration through the normal registry/schema/capability/dispatch path. The caller supplies only a relative path (`.` for the workspace root), offset and requested number of entries. The host resolves the private or shared session workspace from authenticated saved authority. The operation rechecks access before returning names.

`app/workspace/list_directory.ep` uses the installed Darwin arm64 directory ABI: descriptor-relative no-follow directory opens, fdopendir/readdir/closedir, and explicit end/error handling. It lists symlinks as entries but never follows them. Filenames must be UTF-8; unsupported names return filename-not-utf8 instead of malformed JSON. Native entry types are observations, not permission grants or guaranteed current filesystem state.

Pages follow filesystem enumeration order. They are not immutable snapshots: modifications can change ordering, so restart offset zero after directory changes. The requested page size is supplied by the caller, with no hardcoded entry cap. Each root enumeration opens a separate directory description so repeated calls do not inherit another enumeration's cursor.

Tests: `tests/workspace/test_directory_list.ep` verifies Unicode names, one-entry pages and end markers, repeated enumeration on one root descriptor, private-user separation, revocation, path traversal denial and symlink non-following. `tests/agent/test_workspace_list_loop.ep` supplies a streamed tool request through the normal agent dispatcher and checks that the returned filename is archived with a valid event chain. The existing shared-workspace test also passes with new listing checks: joined members see the shared file, outsiders do not, and leaving removes listing access. All passed. Private build/results/database evidence: `evidence/phase2/workspace-list-20261016/`.

Directory listing, search, editing and diff are deployed in release `phase2-files-20261016-201157`. Remaining document/data/archive and other named tool families are still part of the existing step 08 work; this document does not mark that step complete.

## Search, editing and diff

`workspace_search` searches a selected UTF-8 file for a literal, case-sensitive query and returns non-overlapping byte offsets, a continuation offset, end flag and SHA256 of the complete observed stream. Use listing to select files. `workspace_diff` compares two selected files and returns one contiguous line-aligned change span with both complete-file digests. It omits equal prefix/suffix lines but does not claim a minimal edit script. Both are workspace.read capabilities.

`workspace_edit_text` is a separate workspace.edit capability. It accepts complete replacement text and the expected old digest. It checks the current file, flushes a private staged sibling, rechecks the digest, then atomically swaps the staged file and target. The displaced original stays at the returned retained_sibling path. Identical desired content reports content-already-present; stale content is refused. The operation is optimistic, not atomic compare-and-swap against external writers. If the displaced file no longer matches the expected digest, concurrent-change-preserved reports the situation without deleting the retained data. Publication uncertainty requires inspection of both files before retrying. A failed publication can leave staged replacement text at the retained sibling path. New replacement files have private 0600 permissions; original permissions remain on the retained original.

The existing UTF-8 scanner now supports an internal complete-text mode (`characters=-1`). Public passage-reading tools continue to require a positive requested character count. Complete mode reads through EOF, validates every byte and hashes that same stream; it imposes no synthetic text-length limit. These search/edit/diff operations currently retain complete text in process memory, so memory use grows with selected file size. Read-window operations remain available for passage access. Directory pages and content reads are observations, not snapshots against uncooperative writers.

Native text-operation checks cover a UTF-8 sequence crossing the 64 KiB read boundary, complete tail preservation, paged search, stale conflict, exact retained-original bytes, retry, revocation, identical-file diff and line-aligned Unicode changes.
