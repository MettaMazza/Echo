# Local video sampling and playback — 18 October 2026

Status: native integration and real-browser/model acceptance passed; deployed to the primary Echo service as `phase2-video-20261018`. This implements the video requirement already present in Phase Two Step 10 and D14; it adds no plan step.

## User workflow and truthful modality boundary

Users upload an original video through the existing attachment picker. Open plays the original verified bytes in the browser with native controls, no autoplay and inline playback on mobile. Browser codec support determines playback; an unsupported codec retains a download path and an explanatory error. Closing the preview stops playback and revokes its temporary URL.

Echo can inspect metadata and request individual frames through `attachment_video`. Metadata is a JSON attachment; each frame is a PNG attachment named with its requested millisecond timestamp. The selected model inspects the PNG through the existing image tool. This is sampled visual observation, not native whole-video or audio comprehension. No maximum video duration, hidden frame quota or forced output resizing is imposed. Decoder timing and diagnostics remain archived. The actual frame time may follow the requested time according to the source's frame boundaries; requested timestamps are not asserted as exact decoded timestamps.

## Implementation and storage

- `app/media/video_request.ep`: strict request validation, owned/shared attachment lookup, metadata/frame argument arrays, local protocol allowlist and process sandbox, advertised tool contract.
- `app/media/video_tool.ep`: immutable call lookup, current authority checks before and after execution, cancellation/revocation monitoring, executable digest check, verified source copy, process output retention and atomic output publication.
- `app/media/shared_authority.ep`, `app/security/tool_policy.ep`, `app/agent/tool_dispatch.ep`, `app/tools/attachment_tools.ep` and `app/tools/tool_contract.ep`: existing authority and durable tool-ledger integration. Model text does not supply trusted run/call identity.
- `app/web/attachments.ep`: immutable derived-source lineage is committed with the output attachment, never afterward. Private sources cannot enter a shared conversation through this tool.
- `app/archive/attachment_visibility.ep`: exact ancestry propagates automatic-use exclusion to derived metadata and frames. Recursive traversal uses recorded identities, not text similarity. Explicit rereading remains allowed under current access rights, as requested. Restore of an original does not override a separately excluded derivative.
- `app/web/source_reads.ep`: successful video outputs appear with the parent reply as ordinary attachments. `app/web/activity.ep` reports local video processing.
- `app/ui/client.ep`: original video preview, media cleanup and inherited-exclusion display. Existing audio controls are retained.

The decoder is FFmpeg 9.0.2 built from its upstream source using Apple Clang, with networking disabled at build time and in the per-operation sandbox. FFmpeg/ffprobe are external native dependencies; application logic and regression tests remain Ernos Plain. Installed executables run locally; source/build storage and canonical media artifacts use One Touch. The host profile pins both executable SHA-256 hashes through `ECHO_VIDEO_PROFILE`; `ECHO_VIDEO_ROOT` identifies private operation directories. There is no cloud processing or separate language model for video frames.

## Evidence and remaining acceptance

`tests/media/test_video_request.ep` covers request/argument construction. `tests/media/test_video_tool.ep` passed real local metadata decoding and PNG extraction through scripted model calls, original provenance, shared audience access, foreign denial, inherited forgetting/restoration with explicit reread, no completed-call replay, and attachment inclusion in the reply payload. This fixture does not establish model recognition.

The isolated browser uploaded a 4-second, 320 × 240 synthetic clip. Native browser playback reached `ended=true`, `currentTime=4`, `readyState=4`. A real-model request then asked for metadata and samples at 1000 and 3000 ms, image inspection, colour reports, sampled-frame attachments and explicit sampling disclosure. The model completed metadata inspection and both image reads, correctly reporting four seconds, 320 × 240, red at 1000 ms and blue at 3000 ms, and distinguishing sampled vision from whole-video/audio observation. Both PNG thumbnails and their Download buttons appeared beside the final reply. The first reply nevertheless incorrectly said download controls were unavailable after passing attachment IDs to `attach_file`, which accepts workspace paths. The video receipt and tool descriptions now explain automatic publication; the missing-source recovery explicitly distinguishes attachment IDs from paths. A second run returned a freshly sampled blue frame at 2000 ms and correctly described its download control, although it still made the unnecessary rejected call. The actual browser Download button saved the exact 810-byte PNG with SHA-256 `bb5c1fa68c1d1ac6147cbc3bbf929580a396ca17dbeb3b4cf02988b7be7a5241`. The final guidance revision passed a focused real-model follow-up: a new frame was sampled, inspected and returned visibly with its Download control, without another `attach_file` call. Earlier rejected calls remain in the archive.

Opening a video initially left its controls behind the fixed composer when the picker was expanded. The preview now closes that picker and scrolls the video into view after metadata loads; observed video bounds were y=152–392 and the composer began at y=449. Audio layout is unchanged. The exact tested server/client were deployed; production browser upload, verified preview and playback to completion passed. The server and served client hashes matched, and both decoder executable pins were verified. Existing workers and inference were preserved.

The initial candidate launch supplied a plain HTTP URL in the optional HTTPS gateway-origin argument and was correctly refused. The launch configuration was corrected by omitting that argument for the loopback-only candidate. The fresh candidate archive was then initialized through the existing native migration chain before model work; no production archive was changed for setup.

## Reproducing the local dependency configuration

The native decoder was configured with `--disable-network --disable-autodetect --enable-zlib --enable-videotoolbox --enable-audiotoolbox --disable-doc --disable-ffplay`. The host JSON profile supplies `ffmpeg`, `ffmpeg_sha256`, `ffprobe` and `ffprobe_sha256`; executable paths are absolute and their hashes are checked before launch. `ECHO_VIDEO_ROOT` must identify the private artifact directory. These are deployment configuration values, not model arguments. A different build must record its own executable hashes.

The public application source commit is `b2d12bd`. Release provenance binds the committed app/test source snapshot to the rebuilt server and client. Unchanged helper executables retain their existing component provenance; rebuilding the server does not relabel their source history.
