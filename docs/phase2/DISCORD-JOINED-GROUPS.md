## Mention offers and explicit public seeds — candidate, 21 October

The candidate records an immutable offer when an admitted public message tags another human account. Duplicate mentions and Gateway replay reuse one offer. It does not select a group or join anyone. `/group create source:<message-id>` binds acceptance to the original author, guild and channel, with a fresh source/access check in the command executor. Repeating acceptance under a different interaction identity still refers to the same source-bound group. Each invitation has an immutable membership operation: a retry after the invitee leaves does not invite them again. Target accounts must self-join.

Only the original public message text and its author/source identifiers are imported as a source record. Neither participant's personal session is inherited. A current member's new audience session receives its own immutable import receipt. The context composer carries this attributed record through compaction as source evidence, separately from the new user instruction, and checks the admitted group's current membership. Attachments are not silently copied by this text-seed path. This is transport/context plumbing; existing identity and expression policy text is unchanged.

## Archive, reopening and expiry — candidate, 21 October

The lifecycle candidate adds creator-only `/group archive`, `/group reopen` and `/group expire`, all requiring the current revision. Expiry takes an absolute Unix timestamp in seconds; inspect reports the stored deadline and active/archived/expired status. The underlying receipt stores milliseconds. Deadline enforcement uses the database clock at second resolution; no background expiry job is needed. This is a candidate, not yet registered or deployed.

Lifecycle operations are immutable and advance the existing audience revision atomically with an audience snapshot. Reopening therefore does not revive work admitted before closure. Exact operation replay returns its old receipt without changing the latest state; conflicting reuse and stale revisions are rejected. A group creator must still be joined, and ordinary members cannot archive the group. Closure blocks new routing/selection, invitations/joins, current run authority, tool/workspace dispatch and reply export through the existing shared authorization checks. Leave/removal remain available. Historical records are retained under historical audience checks; this does not grant later members access or import private conversations. Historical UI navigation and full live lifecycle acceptance still need qualification.

Native `test_group_lifecycle` passed creator denial, closure, stale selection/route refusal, blocked invitation, historical read retention, database restart, exact replay, conflicting revision, reopening without reviving old runs, deadline enforcement and rejected past expiry. `test_group_options` passed strict archive/reopen/expiry fields, missing deadlines and integer overflow rejection. `test_group_control` passed archive/inspect/reopen alongside existing invite/join/leave controls.
