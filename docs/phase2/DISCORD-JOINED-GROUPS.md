# Joined Discord conversations — implementation in progress

This implements original step 14 and the group-control row of Discord UI parity. It is not a new completion denominator. Existing personal Discord silos stay the default; no joined-group command is registered or deployed yet.

The candidate reuses `group_create`, versioned invitations/self-join/removal, captured audiences, and `group_route`. Discord group IDs bind the authenticated guild, channel and source operation. Only groups with the connector's joined-group origin may be selected; browser groups and personal singleton silos cannot be adopted. Selection is an append-only per-principal/guild/channel record with exact replay/conflict checks. Selecting an empty group explicitly returns to personal routing. Removed members receive an access refusal instead of having an already-intended group message silently moved into another conversation.

A mention is an invitation, not consent to join. Existing membership rules require the invited principal to join itself; membership never grants admin authority. The initial group has no imported private ancestry. Membership changes create a fresh audience revision; prior sources are eligible only under the existing audience and explicit-sharing rules.

Native foundation and authenticated intake tests now pass. Two test principals select the same joined group and retain separate personal history. Replayed intake is pinned to its original group even after a new selection; removed members cannot silently fall back into a different conversation. A pure admitted-audience lookup is used by final reply and job lineage validation. The joined reply fixture passes after switching back to personal routing, and the existing UTF-8 chunking, resumed final, reopen/idempotence and revoked-authority output regression passes.

The `/group` candidate supports create, list, inspect, invite, join, leave, remove, open and personal. Native option tests reject incorrect Discord user types, duplicates, missing fields and invalid revisions. Native control tests pass create/select, invitation without forced membership, self-join/replay, foreign-channel denial, revision inspection and leave-to-personal routing. Native command registration/admission tests pass exact create/list intake, replay, forged-body rejection and reopen. The control uses the existing private command response; conversation prompts and replies remain in the channel with their original thinking-thread behavior.

History/new/resume now use explicit group selection; export resolves the requested session's exact authorized audience; autonomy admission uses the selected group and preserves existing-run binding. The personal new/resume/export and admin-autonomy regressions pass, as does shared `/new` with a second joined actor routing to the same fresh session. Background delegation/schedule output retains its original audience and rejects unknown/revoked origins after reopen. The existing accepted/staged audio session-retry regression passes. Joined and personal media/export variants now both pass; the production `discord_actions` executable builds. This is native acceptance, not live network acceptance. Actual mention invitations, multi-user/restart/compaction and live UI acceptance remain unfinished. No joined command has been registered remotely and no candidate has been deployed. Do not label these native results as live joined-conversation acceptance.
