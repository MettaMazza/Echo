# Runtime-bound capability memories

`system_inspect` now returns `runtime_binding`: the deployed executable/helper build fingerprint, a hash of the run's selected provider profile (including a routed vision profile when present), and a hash identifying the installed architecture/identity file contents. Prompt text and credentials are not copied into this identity. The source tool result remains the immutable observation.

Private and shared graph results and automatic recalled context report `runtime_status`. `current` means those runtime identities match; it is not a new measurement, verified truth or a guarantee of current availability. `stale-runtime` means at least one identity changed. `unavailable` means a bound observation lacks a usable build/provider identity. `unbound` means no runtime qualification was recorded; legacy observations are not silently certified. Historical records and correction links are retained. Later model promotion/configuration tooling must preserve versioned provider profiles and build fingerprints; this is not a hash of model weights reread on every chat turn.

The native regression calls actual system inspection and checks matching and changed build, provider and identity bindings through both private/shared graph traversal and automatic context. It verifies archive integrity. Run 02 passed without that diagnostic. The existing optional vision-profile lookup diagnostic remains in the retained output. This is actual inspection plus native memory qualification, not an additional model-generated conversational test.
