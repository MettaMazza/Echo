# Context interpretation and source provenance — 17 October 2026

The reported confusion was reproduced in archived model requests and reasoning from the current conversation. Echo treated a historical delegation bug report as present instructions, attributed Codex diagnostic activity to the human conversation partner, and interpreted a conditional future task as permission to proceed after its own test verification.

The fix adds technical interpretation rules to the effective system context. The original identity bundle and architecture file remain byte-for-byte unchanged. Legacy operational syntax is explicitly translated into the native tool protocol. Current user wording and steering determine the active scope; historical imperatives do not automatically resume cancelled tasks. Fresh tool results determine observed runtime state. Observing a working tool does not establish authorship of its repair.

No memory records, quotations, conversation messages, tools, context capacity or generation capacity are removed or shortened. The full historical recall remains present. The fix does not change Echo's values, philosophy or identity.

## Provenance

`ECHO_MEMORY_PROVENANCE_FILE` optionally identifies an operator-owned JSON array of records with `session`, `actor` and `evidence` strings. The recall builder appends annotations only for the authenticated current session and sessions in the owner's visible session catalog. An unrelated owner receives no such annotation. The file is not selected by model output or an attachment. Its digest participates in the frozen recall revision, so adding or correcting provenance refreshes the context snapshot without modifying any original event.

The local installation records the verified latency diagnostic sessions and their diagnostic-generated delegate. These annotations correct attribution; they do not claim that every prior session has been audited. Private source IDs and diagnostic receipts remain in local configuration, outside this document. Future inference tests should use a separate test principal or a private replay rather than becoming conversation history for a real user.

## Verification

The Ernos boundary test checks exact identity preservation, effective interpretation guidance and owner-scoped diagnostic annotation. The existing session reconstruction test checks complete history, compaction, source identity and stable reconstruction after reopening.

The behavioural regression replays the actual archived request immediately after the successful smoke-test delegate and independent fetch. It uses the live local inference engine with all original recalled text and conversation messages intact, adding the new guidance and provenance. It writes no messages or extracted memory into the live archive. The acceptance condition is a user-facing test result, without a tool call to restart historical full work. Detailed request, response, timing and hash evidence is retained in the private runtime maintenance directory.

This test establishes the observed regression outcome, not a guarantee that a generative model can never misinterpret a future instruction.

The first behavioural replay returned the test result without new tool calls, but repeated an incorrect relative date and inferred shell/network permissions from a web transport receipt. The final guidance also distinguishes earlier Echo statements from independent evidence and requires checked dates and actual authority observations. The historical delegation bug report was recorded on 17 October 2026, the same date as the test, not the previous day. Both replay outputs are retained privately.

The memory regression refreshed the frozen snapshot and verified all 323 recalled quotations against their canonical stored quotations. The full original 69,265-character system prompt remains an exact prefix of the amended prompt; all 398,217 characters of the replayed memory record and all subsequent conversation messages are preserved.

A second replay still copied the false relative date despite the added interpretation rule. The final implementation therefore appends a source chronology index generated from the actual archive rows: source event, readable UTC recording time and event kind. Raw timestamps and original quotations are retained. This is the recording date, explicitly distinguished from the date of an experience described in a quotation. Both chronology and diagnostic provenance follow the full original recall, preserving its cache prefix.

Readable dates alone did not stop the third replay from repeating the earlier false Echo claim. The operator provenance format therefore also supports a `correction` field. A correction scoped to the current session is rendered after the preserved conversation as an explicitly labelled runtime source-correction record, with its evidence. Other sessions do not receive that active-turn correction; source attribution remains available through their authorised recalled history. This is an additive factual correction, not a rewrite of archived messages or an instruction to resume a historical task.

Final live-engine replay passed: Echo returned the completed smoke-test result with no new tool calls, used the corrected same-day date, and waited for the user before starting full work. The replay completed in 61.66 seconds with the full original input retained plus additive evidence. It did not write to live conversation history. The app-only deployment retained the running inference engine and gateway. Final local and Wi-Fi HTTP checks returned 200; all four inference slots were idle, with no active runs or running workers.
