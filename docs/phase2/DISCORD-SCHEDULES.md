# Discord schedule controls — 21 October 2026

Deployed for live acceptance; full live acceptance is not yet complete. Schedule creation continues through Echo's existing scoped `schedule` tool. The new `/schedules` command adds explicit human list, inspect, occurrences and cancel controls, using a conversation ID from `/history`. It does not create a second scheduler.

The actor comes from authenticated Discord intake and the schedule must belong to that principal in the exact Discord conversation/channel. Linked Host identity and administrator status do not export private schedules. List and occurrence results use a `next_after` cursor. Cancelling stops future reservations; previously reserved or running occurrences retain their identities and ordinary cancellation controls.

The original interaction binds the command, actor, channel and options. Cancellation has a durable source event, repeated requests are idempotent, and conflicting reuse is rejected. Response bytes are frozen for delivery recovery, with current membership/ownership checked again before reuse. The receipt is private to the requesting account, unlike public conversation replies and their Thinking threads.

## Gateway discovery regression

The subsequent restart exposed an independent connection failure: authenticated Discord discovery returned `reset_after: 0`, which the old parser rejected as invalid. No new user message was received during that offline interval. The parser now accepts zero as a distinct case, permits at most one Identify from that fresh positive server allowance, preserves the five-second concurrency bucket, and requires rediscovery for another reservation. Exhausted zero-reset discovery backs off instead of spinning. It does not invent a future reset or unlimited quota. Positive-window behavior remains unchanged. Native cases passed and the deployed gateway reached READY and heartbeat acknowledgement; a fresh labelled request was admitted afterward. The offline test was not silently replayed.
