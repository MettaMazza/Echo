# Execution helper catalogue consistency — 22 October 2026

The Discord worker and its separate scoped execution helper must use the same tool-policy catalogue. A rebuilt worker alone is insufficient: the helper rechecks shared history and correctly rejects unknown capabilities. The previously installed 21 October helper did not know the new Discord post/thread/role/member tools. This made a conversation containing their results fail with `workspace-unavailable` even though creating and reading workspace files worked.

The original failure and the explicit reproduction are retained. The fix rebuilds `execute_guardian` from the qualified release source, retains the pinned Ernos compiler and sandbox, and installs it in a new immutable execution release. The local deployment launcher now checks a qualification receipt, hashes every execution artifact, compares the helper's policy-source SHA with the release's current policy source, and records the execution release in the worker registry. A policy change requires helper requalification before launch; no runtime compiler or permission change was made.

Native execution acceptance passed real scoped command execution, compiling/running an Ernos fixture, scoped SQLite operations, restart/output retrieval and cross-session output denial. Separate stop and revocation tests killed/reaped the actual command and cancelled the run. Two real Discord turns then read the existing `member-workspace-629.txt` with `/bin/cat` and checked its length with `/usr/bin/wc`; retained stdout was exactly `meadow-629` and a ten-byte count, with clean exit and no file mutation. Normal marker and authenticated-username recall remained intact. Both replies and final Speak controls survived reload. No TTS or model configuration changed.

Canonical private evidence: `evidence/phase2/discord-execution-catalog-20261022/` (`candidate.json`, `native.json`, deployment records, `live-turns.json`, `actual-stdout.json`, `ui-checks.json`). The original `workspace-unavailable` receipt is not erased or reclassified as success. This closes this execution regression, not the full Step 15 catalogue or Step 16 integrated gate.
