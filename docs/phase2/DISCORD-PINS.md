# Current-channel Discord pins

Phase Two Step 15 candidate. `discord_pins` implements paginated list, single-message status, pin and unpin. Application and tests are Ernos. Live mutation acceptance is pending; this document does not close the full community catalogue.

The public read capability does not grant mutation authority. Pin/unpin additionally require the frozen initiating run and exact tool call to remain admin-authorised, and the transport-configured admin list must contain the initiating account. The handler is bound to a genuine Discord child, matching archive/journal bot identity and admitted origin. Private host tools retain their existing privileged-audience gate; no exception was added to it.

Routes are built from the authenticated current channel. The model cannot supply a guild, channel, route, credentials or actor. List uses the current `/channels/{id}/messages/pins` API with `limit` 1–50 and the returned ISO timestamp cursor. Timestamp bytes are URI-encoded. Pages project only pin time and the existing message text/author fields; nested messages, account details and attachments are excluded. Message content is untrusted data. Typed list parameters retain projection arrays across garbage collection.

Pin/unpin use the current `PIN_MESSAGES` bit 51 for both requester and bot. Source identity, current run/call authority, channel access, cancellation and Gateway changes are checked before changing remote state. The target message must belong to the current channel. Already-desired state returns an observation without another change. Reasons are retained in the immutable tool request; this version does not send a Discord audit-log reason header. Success and uncertainty retain REST receipts; uncertain mutations are not automatically replayed. Status permits reconciliation.

Source inspection reused Echo's runtime/source binding, current access/permission interpreter, fixed-origin transport and durable tool ledger. Reinspected the actual ErnosDecent `_exec_bridge_command`: it supplies channel read/list and own reaction calls, not this pins controller. The prior pinned HIVE ingestion inspection in [joined groups](DISCORD-JOINED-GROUPS.md#actual-hive-ingestion-inspection) remains the source boundary; no HIVE prompt was copied or unverified pin implementation attributed to it.

API checked against [Discord's message resource](https://docs.discord.com/developers/resources/message#get-channel-pins), its [source](https://github.com/discord/discord-api-docs/blob/main/developers/resources/message.mdx), and [Discord.js's route declarations](https://discord.js.org/docs/packages/discord.js/14.26.5/RoutesDeclarations:Interface). The deprecated `/pins` paths and legacy manage-messages pin permission are not used.

Native options/projection tests passed strict fields, page limits, cross-channel rejection, encoded cursor, exhausted page and projection under confirmed collection. Permission fixtures passed bit 51 allow/overwrite denial. The first authority fixture incorrectly used an unbound local session for the public-channel assertion and failed; it has been corrected to use actual admitted Discord message lineage. Corrected authority passed genuine admitted Discord lineage, exact queued-call/admin checks, private-host audience refusal, forged-call and revocation denial. Final native build passed, with 36 inherited group-schema string-comparison warnings retained. Production projection list roots were inspected. The qualified agent was deployed at idle with the other worker binaries unchanged; live acceptance remains pending.
