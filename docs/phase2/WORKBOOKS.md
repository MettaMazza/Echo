# XLSX workbook reader

Step 08 now has `workspace_read_workbook`: `path`, exact `sheet` name, zero-based stored-cell `offset`, and positive page size `cells`. Empty sheet returns the sheet catalogue. The tool uses the authenticated workspace read boundary, regular-file descriptors, macOS libarchive and libxml2. It never extracts package paths onto the host, executes macros, follows external relationships or recalculates formulas.

Implementation: `app/workspace/workbook_read.ep`, `workbook_parts.ep`, and `xml_nodes.ep`; existing workspace schema, dispatcher and read policy expose the operation. It discovers the workbook through the package root relationship and sheets/shared strings through workbook relationships. Relationship paths are normalized inside the package. Relationship attribute prefixes may vary; namespace-qualified IDs are resolved. Duplicate XML parts and malformed XML fail explicitly. XML DTDs/entities are rejected and network parsing is disabled.

Results retain exact numeric spelling, resolved shared/inline text, original stored values, cell reference, type and style index, formula text and shared-formula metadata. Workbook date system and source SHA256 accompany results. Cached formula results may be stale; no recalculation or date/number-format rendering is implied. Offsets count actual stored cells, not every position in a rectangular range. Empty stored cells are retained. Hidden sheet state is visible in the catalogue.

The reader retains XML parts in memory, parses complete selected documents and pages returned cells. XML uses UTF-8; UTF-16 parts, legacy XLS, encrypted files and URI-escaped relationship targets are not supported by this reader. libxml2's signed-int memory API imposes its native per-part size bound. The source digest is observed before parsing, not a snapshot against a concurrent external writer. ZIP part names now come from validated original UTF-8/ASCII local headers, avoiding macOS Unicode normalization; legacy non-UTF-8 names and ambiguous headers fail explicitly. This reader does not edit, calculate or render workbooks. Workbook creation and editing are described below. Calculation/rendering limitations do not imply extra plan steps.

## Creating workbooks

`workspace_create_workbook` accepts a new `path` and `sheets`, each containing `name` and `rows`. Rows are arrays of JSON scalars or formula objects. Strings become inline text (including leading zeros and literal leading equals signs), numbers retain their supplied spelling, booleans remain boolean cells, and nulls become explicit empty cells. Formula objects accept `formula` and optional scalar `cached`; a leading equals sign is removed from formula syntax. The cache is supplied data, not a computed result. The workbook asks spreadsheet applications to recalculate on opening. Application numeric precision can differ from the exact XML spelling; use strings for identifiers and precision-sensitive text.

Implementation: `workbook_create.ep` generates package XML through the existing parser/escaping functions. `create_archive.ep` now shares its exclusive staged publication path with an internal XML-parts writer. This internal mode is not accepted by the general archive tool. Existing-file preservation, source-relative tool authority, hashes, crash-stage handling and publication-uncertain reporting remain unchanged. No temporary XML files, shell commands, external services or macro execution are involved.

Creation supports multiple unstyled sheets and the Excel row/column and sheet-name constraints, rather than model-dependent limits. See Microsoft's [worksheet naming rules](https://support.microsoft.com/en-gb/excel/rename-a-worksheet). It does not author charts, style layouts or calculate formulas. Those are capability limits, not new completion checklist entries.

## Editing existing workbooks

`workspace_edit_workbook` accepts source `path`, a NEW `destination`, `expected_sha256`, and `replacements` containing existing `part` names and their complete replacement `xml`. Echo can inspect those parts with archive listing/extraction and text reading before editing. It is a full XML-part editor, not a lossy conversion from cells: styles, charts, media and other unselected entry payloads remain byte-identical. The original workbook is preserved. Changed parts must remain well-formed XML with the same root name/namespace. There is no formula calculation or automatic dependency rewriting; the caller must keep affected formula references, caches and calculation settings consistent. It cannot add/delete package parts or modify signed workbooks without a separate re-signing workflow.

`workbook_edit.ep` validates input and workbook identity; `archive_patch.ep` streams unchanged ZIP entry payloads and rechecks the source digest after copying. `create_archive.ep` supplies exclusive staged output, output hash and flush semantics. A concurrent writer that changes and restores bytes during copying is not prevented by the before/after hash checks. ZIP compression and container metadata can change; byte preservation applies to unselected payloads and exact logical entry names, not the whole ZIP file. Internal ZIP member paths never become host extraction paths.

The initial native-library clone path normalized a Unicode filename and omitted its UTF-8 flag. It was caught by independent ZIP inspection before deployment. The fix obtains names from the format-bounded local-header range ending at the reader's current data offset, rejects ambiguous candidates, sets the clone's unconverted pathname and writes UTF-8 headers. Native `test_zip_names.ep` verifies original and edited names exactly, including NFC café. The public header-position API points to a preceding consumed location for seekable ZIP and was not usable here; `archive_filter_bytes` provides the verified current data boundary. References: [libarchive ZIP reader source](https://github.com/libarchive/libarchive/blob/master/libarchive/archive_read_support_format_zip.c).
