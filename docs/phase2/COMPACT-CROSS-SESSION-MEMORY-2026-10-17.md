# Compact cross-session memory — 17 October 2026

## Cause and change

The 15-message session's rejected request contained 263,293 tokens against the loaded 262,144-token context. Cross-session recall alone occupied 210,204 tokens. Repeated per-claim field names, hashes, source identifiers and dates inflated the representation; append-only snapshots also retained original messages after derived extraction finished.

The private recall representation now groups exact claims by shared source. Each source row contains event ID, session ID, readable archive timestamp, source kind, runtime status and claim rows. Each claim row retains kind, subject, category, exact quotation, evidence classification, event time and validity end. Empty dates remain empty. Echo-authored source labels display Echo. Canonical claim IDs, digests, ingestion timestamps and all original bytes remain in the existing archive and knowledge graph, available through memory_read/memory_graph. The context format has an explicit field legend. No claim-count or text-length cap, new summary model, source rewrite, or arbitrary context reduction was introduced.

New turns reconstruct this compact canonical view rather than extending a previous turn's raw memory dump. Unindexed original messages remain present until extraction completes; after that, new snapshots use the exact extracted quotations. Frozen snapshots remain stable within a run. Revision versioning prevents reuse of an old-format snapshot. Existing visibility, expiry, correction, runtime and access checks still apply. Group memory behavior is unchanged.

This is a lossless transformation of the selected claim quotations and semantic fields, not a claim that extraction itself is lossless or that the whole archive fits indefinitely in finite context. Fine-grained provenance metadata is retrieved rather than repeated in every prompt. Original records remain authoritative and rereadable.
