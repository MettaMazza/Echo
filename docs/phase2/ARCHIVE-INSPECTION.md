# Scoped archive inspection

Step 08 `workspace_archive_list` inspects ZIP, TAR and gzip TAR metadata from a regular file opened through the authenticated session workspace. Arguments are `path`, zero-based `offset`, and positive `entries`. Returns indexed entry names, numeric file type, declared byte size, total count, next offset, end state and SHA256 of the source bytes observed before parsing.

It uses the existing macOS libarchive dependency, through Ernos FFI, without a disk extractor or archive-specified commands. Entry names, including traversal paths and links, remain inert metadata. Duplicate names retain separate indexes. macOS may normalize decoded Unicode names; the result states this rather than claiming raw filename bytes. The original archive is not rewritten. Full header scanning is not proof that every compressed payload checksum is valid. Concurrent external writers can change a file between hashing and parsing; the digest is an observation, not an atomic snapshot.

## Selected-file extraction

`workspace_archive_extract` accepts archive path, zero-based entry index, source_sha256 from listing, and an explicit workspace destination. It checks the observed source digest before reading the selected entry, rejects links and non-regular entries, ignores stored paths/permissions, and stages binary output with mode 0600. Exclusive rename preserves an existing destination; successful results include extracted SHA256 and byte count. The parent directory must exist. A process crash can leave a `.echo-pending-*` stage; publication-uncertain requires inspecting the destination before retry. The pre-read source digest is not an atomic snapshot against concurrent external writes.

## Archive creation and live invocation

`workspace_archive_create` creates ZIP, TAR or gzip TAR from an explicit list of regular workspace files into a new workspace path. Binary data streams through the native writer; no shell, recursive host traversal or stored executable permissions are used. Files retain relative names with mode 0600. Duplicate source paths are rejected. An exclusive staged publication preserves existing destinations; successful output includes archive hash and byte length. Source files should remain unchanged during creation; size changes cause failure, while same-size external edits are not an atomic snapshot. Crash recovery and publication-uncertain follow the extraction staging rules.
