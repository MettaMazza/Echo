# Retained text parsing — 22 October 2026

The channel acceptance failure exposed an application-wide dependency on the runtime's `string_split`. The retained native crash shows an invalid free during list construction: retaining the returned list does not protect it while the runtime is still allocating its elements. The earlier header-specific direct scanner remains in place. No compiler or runtime source was changed.

`app/retained_text.ep` now supplies `retained_text_split`: the caller creates and retains an empty destination list and passes it into a typed function. Input strings, destination and allocated segments remain reachable during collection. All 23 application files which called the unsafe splitter now use this convention (the resident protocol's slash check uses direct containment). Empty segments, empty delimiters, repeated and multi-byte delimiters retain the previous semantics. A nonempty destination is rejected without modification.
