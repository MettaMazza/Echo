# Corrected-fact recall — Step 09

The existing evidence graph already stores immutable correction chains: the successor references the earlier assertion, and graph traversal returns both directions. A replacement must match the original principal, kind, subject and predicate. Separate contradictory evidence remains separate. The ordinary recalled context selects current, visible, unexpired claims and never resurrects a superseded assertion simply because its correction was forgotten.

The current change adds event time, validity end, ingestion time, explicitly named source-recording time and the superseded assertion ID to the automatic recall representation. Previously those fields were available through graph tools but omitted from automatically injected memory. Original event IDs, digests and source text remain intact. This change does not infer correction links between unrelated quotations or rewrite historical claims.

`tests/memory/test_corrected_recall.ep` passes against an isolated internal-drive database. It proves current-fact selection across sessions, temporal/correction metadata, historical graph access, foreign-owner denial, reopen, forgetting without resurrection, explicit restoration, intact archives and principal revocation.

`tests/memory/test_live_corrected_recall.ep` asks the actual local model to follow the correction chain through `memory_graph` after database reopen in a separate session. The first model run passed graph traversal and returned the correct current name, date and source ID. Its independent automatic extraction returned a bare JSON array and logged `memory-missing-items`; that evidence is retained. The grounder now wraps a bare array as the ordinary memories collection before applying the existing source and quotation validation. A second run returned fenced JSON and logged `memory-invalid-json`; the normalizer now also accepts a complete outer JSON Markdown fence. Native coverage exercises object, array and fenced variants. The final live test additionally requires no memory failure and no pending source ingestion. The final retest passed against `live-03.sqlite`, with three graph calls, correct current fact/date/source, no automatic-memory failure, no pending ingestion and intact archive chains.
