# Admin Code/Git workflow

Original step 08 includes Code/Git operations. `host_git` accepts an absolute working directory, a Git subcommand and separate argument strings. It invokes installed `/usr/bin/git --no-pager -C ...` through the existing execution guardian. This provides repository status/diff/history/source queries, branch/worktree operations, patch application, staging/commits and native remote operations. `init` and `clone` use an existing parent directory as the working directory. Git controls its native command semantics; no added commit-count or output-size cap is imposed.

The tool is advertised only to an initiating admin in an eligible audience, with configured host protections. The immutable request determines its arguments. Guest access, revocation and promotion after submission do not grant execution. The guardian records argv, sandbox digest, original stdout/stderr, cancellation and exit receipts. `workspace_output_next` reads the output. Repository and argument text are not concatenated into a shell command. Git itself may invoke configured hooks, aliases or credential helpers; these inherit the host sandbox. Commands run as the Mac service account, not automatically as root.

Protected Echo installation/state/model roots remain non-writable and connector-secret roots remain inaccessible. Work on an ordinary repository or a candidate checkout; use the charter controller for protected installation changes. Git mutations can discard changes or rewrite history, and remote operations can publish data. Echo must follow the initiating task, inspect status/diff, preserve unrelated work and reconcile an uncertain command before retrying. Do not pass secrets as arguments: requests and output are retained. Exit status interpretation follows the operation: for example, diff with exit-code can signal differences rather than execution failure.
