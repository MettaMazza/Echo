## Explicit clock context

`app/context/clock.ep` formats host Unix milliseconds through macOS `localtime_r`, `gmtime_r` and `strftime`. Each user event with its canonical `unix-ms:` timestamp gets a separate runtime clock observation immediately before the original message during request reconstruction. It includes weekday, calendar date, hours/minutes/seconds, timezone abbreviation, numeric UTC offset, UTC time and Unix milliseconds. The original message bytes and archive digest are not modified. Historical timestamps remain historical. Echo is explicitly told to use `system_inspect` for a fresh clock during a long task; its observation now includes the same human-readable time. This describes the host timezone, not an assumed timezone for a phone or Discord user.

No changing clock is inserted into the shared identity prefix. Reconstructing a turn produces the same timestamp, so clock updates do not continually invalidate its prompt cache. Older events without a supported timestamp do not receive invented dates. Native epoch/current-clock and real submission/reconstruction checks passed.

The example llama service profile describes this installed model and 512 GiB host. Other installations must discover their model context and choose concurrency/cache allocation within their own available memory; these values are not universal defaults.
