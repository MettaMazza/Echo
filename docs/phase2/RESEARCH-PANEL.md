# Retained web research in conversation messages

The per-message **Web research** disclosure shows observed web_fetch, web_search and web_follow results with their URL, operation status, result event and original-body SHA-256. Open and Download use the existing authenticated attachment endpoints. Remote URLs render as text and never load automatically; fetched HTML is not inserted into the conversation DOM.

The transcript reader joins the requested session/run to observed tool calls, their original request/result events, a same-session web_fetch_receipt, and the registered original body matching the returned body SHA-256. References with another session, mismatched digest or missing receipt are omitted. The existing transcript route remains responsible for current device/audience authorization. Fetch results are deliberately separate from **Sources read**: a successful fetch does not establish that Echo read the page or verified a claim. Failed HTTP responses and search challenges can retain useful originals.

`tests/web/test_research_sources.ep` verifies exact body/receipt binding, wrong digest rejection, foreign receipt/body exclusion, run isolation and archive integrity. `tests/web/research_panel_browser.ep` renders the production UI function with synthetic status/URL data, verifying disclosure, controls and literal rendering. Evidence is retained under `evidence/phase2/research-panel-20261017/`. Integrated desktop acceptance now also passed using a disposable consistent copy of the earlier real-model web-fetch archive: the authenticated UI displayed the recorded reply and fetch receipt, opened the retained HTML as literal source text, and downloaded all 577 bytes matching both the original file and recorded SHA-256. The original model run was reused rather than regenerated. This does not claim physical-phone acceptance.
