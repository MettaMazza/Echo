# Echo's four runtime QoL additions

Implements Echo's `echo-qol-spec-v1.0.0` request of 16 November 2026. These additions reuse scratchpad revisions, authorized session discovery, automatic-recall snapshots, and the protected controller's effect ledger. They do not change memory permissions, grant tools new authority, change model reasoning settings, or reduce the context window.

## Working state

With `me_file` enabled, reserved scratchpad note `me` is automatically included as a labeled system-context block near the current turn. It is not selected by a search query. Private notes retain their existing principal scope; public notes retain their exact audience scope. Private notes are never substituted into a public conversation or another user's context.

Use the existing `scratchpad` tool to read and write `me`. Updates require its current `previous_revision`. The fixed headings are CURRENT PROJECTS, POSITIONS HELD, OPEN QUESTIONS, FOR THIS CONVERSATION, and LAST UPDATED / SPEC VERSION. The write cap is 4,000 model tokens including the working-state header. `expires_at` sets a future UTC expiry for open questions; omission defaults to seven days. Expired questions are omitted from the active block with an archive warning, while the original revision remains available. Malformed or oversized legacy notes degrade to a warning, rather than breaking context assembly.

A missing note is initialized with a visible revision attributed in its text to the operator's implementation of Echo's request. It lists this specification and its acceptance tests. Echo can then maintain the note itself.

## Recall coverage and session index

New automatic-recall snapshots record a three-line manifest with query input/hash, selection mode, objective timestamp boundary, considered/selected counts, source timestamp range, and an explicit omission-versus-nonexistence distinction. The current manifest accompanies the working-context block; previously retained recall remains historical context. Older snapshots without a manifest are explicitly labeled unavailable rather than given invented metadata.

The existing authorized `memory_sessions` operation supplies a compact index at run start. Rows include session identifier/label, dates, principal identifiers and message count. The current archive is limited to twelve entries with a continuation cursor; an explicitly linked private archive may contribute six entries through the existing private bridge. Truncation is stated and does not imply that further records do not exist.

## Change notices

The existing administration helper records deployment/revert notices. The protected controller's existing applied/rolled-back effect events are projected on wake through a fixed read-only helper operation, once per run. Only terminal effect type, timestamp and code digest are exported. Private review text, conversation text and host paths are not exported. The controller ledger retains the original evidence and permissions.

The public-safe notice log is `/Library/Application Support/EchoRSI/notices/events.jsonl`; `latest.json` is its atomically replaced bounded view. The wake block includes the latest five notices since the scope's previous conversation checkpoint. Runtime/prompt/provider/tool fingerprints also expose observed changes between conversations. Changes made outside deployment should be recorded explicitly:

```sh
sudo -n /Library/PrivilegedHelperTools/local.echo.admin notice \
  --kind prompt --summary 'Public-safe description of the prompt change.' \
  --version '<version-or-hash>' --actor operator
```

Allowed categories: deployment, revert, prompt, policy, routing, toolset, operator. Summaries must be single-line and public-safe. Do not put private context or credentials in them.

## Disclaimer awareness

The persona section contains Echo's exact requested clause, followed by its guard against manufactured admissions and ritualized introspection. It calls for same-turn inspection when an unsolicited disclaimer is noticed. Long-term frequency improvement requires observation across real conversations; a deployment test cannot establish that trend.

## Flags, latency and rollback

Operator configuration lives at `/Library/Application Support/EchoRSI/notices/qol.json`. Four independent flags are `me_file`, `recall_awareness`, `change_notices`, and `disclaimer_flag`.

```sh
sudo -n /Library/PrivilegedHelperTools/local.echo.admin qol-flag me_file off
sudo -n /Library/PrivilegedHelperTools/local.echo.admin qol-flag me_file on
```

No rebuild is required for flag changes. Other configuration fields select the local tokenizer, notice count and installed public notice view. The protected-ledger refresh is enabled by `refresh_controller_notices`.

The combined added working context and disclaimer clause are checked against a 6,000-token budget. The session index is the first part omitted when the budget is exceeded; warnings distinguish truncation from missing history. Cached blocks are bound to run, note revision/expiry, access revision, recall snapshot, runtime/tool identity, notices and configuration. Updating a note does not rewrite the beginning of a long conversation. Warm tool rounds reuse the block. Optional token counting has a one-second cancellation deadline; the privileged notice projection has a 750-ms worker deadline. Neither invokes generation.

Acceptance fixtures: `tests/context/test_qol.ep` and `tests/context/test_qol_config.ep`. Deployment evidence, timings, notice-projection fixtures and model-response evidence are retained in the operator workspace's `qol-implementation-20261116` directory.
