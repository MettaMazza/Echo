# 20 October latency investigation

Status: r33 application changes deployed; latency target remains unresolved. This is not a claim that all replies now finish below 20 seconds.

The requested historical comparison is the 19 October morning session. The 1.864-second statistic measures model dispatch to first output, often reasoning, not a finished answer. Five short single-request follow-ups in that session finished in 13.336, 12.105, 13.491, 16.816 and 11.560 seconds (median 13.336). The initial greeting took 27.057 seconds; a four-request tool turn took 33.712 seconds. These are historical observations with a different model and context, not controlled same-input benchmarks.

## Changes and controlled evidence

- Correction lookup drives indexed event reads from correction links instead of scanning the full archive. The copied-archive query returned identical results, approximately 725 ms versus 7 ms.
- Semantic preparation selects only unindexed authorised quotations before parsing. Three native saved-input runs selected byte-identical records before and after; preparation fell from approximately 2,250 ms to 12 ms, and candidate enumeration from approximately 735 ms to 8 ms. Ranking, source access, corrections and original records remain intact.
- Fixed conversation routing and native-audio policy moved into the cacheable prefix. Short current-turn and actual-media-presence receipts remain at the tail. Reasoning is still enabled, without a new output cap.
- Byte-identical repeated audio parts become explicit references within the provider request. One full native waveform remains for each distinct content part; different formats or metadata are not combined. Source attachments and messages are unchanged. The actual selected WAV remained hash-identical while a request fell from about 3.35 MB to 1.25 MB.
- Audio serialization was tested to avoid constructing an unused image representation and repeatedly escaping encoder-produced base64. Source integrity and access checks remain mandatory.

Native regressions cover selected recall, corrections, stable session recall, cancelled-task context, capability/presence distinction, large multimodal payloads and duplicate-audio preservation. The old corrected-recall test initially failed because it asserted a superseded full-claim prompt representation; it now checks the canonical candidate interface, including correction IDs/dates, foreign exclusion, reopening, forget/restore and revocation. The initial failure is retained in private evidence.

Matched-input isolated trials of larger prompt microbatches, eight CPU threads and quantized KV cache did not justify promotion. All trial endpoints were stopped; the production model retains full-precision KV, native 65,536-token context per slot, native reasoning and the same pinned Thinking weights/projector. Instruct remains retired. Warm's conditioning, acoustic reference, pitch and synthesis helper are unchanged.

## Observed limitations

The first changed-prefix request needed a cold rebuild and took 79.405 seconds. A following warm arithmetic request finished in 9.832 seconds, but this is not representative of every workload. The actual selected audio transcribed correctly in 64.955 seconds after an unnecessary audio-restoration tool call. A word-count follow-up entered prolonged repetitive reasoning and was cancelled; this failure must not be excluded from the account of responsiveness. Changed-instruction recovery correctly quoted the ending in 13.551 seconds. Reattachment and subsequent text/memory turns still took roughly 19–24 seconds in the intermediate builds.

Reload retained the observed replies, audio cards and visible reasoning. Remembered user corrections and native audio follow-ups remained available. Acoustic adjectives generated by the model are not independently verified acoustic measurements. No all-turn latency guarantee is claimed. Full feature-film soak and broader Phase Two/Discord work remain separate open work.

Private timings, original traces and rollback snapshots are retained under the local maintenance evidence directory. Recordings, transcripts, memory excerpts and request payloads are not published.

The r33 audio and image transport tests also passed with a 1 MiB fixture containing every byte value, decoded exactly; ownership, revocation and source receipts remained enforced. Its first post-deployment audio turn took 55.928 seconds with a changed context prefix; the following short text reply, retaining native audio, took 20.242 seconds. This does not meet a claim of consistently faster conversation. A locally derived Q8_0 weight candidate from the same verified Thinking checkpoint is being evaluated; production remains BF16. This is distinct from the earlier rejected KV-cache quantization experiment. No extra model download is required; no automatic promotion is authorised by these notes.
