# Persistent silo scratchpads

Private notes retain their existing principal identity and remain available across that owner's sessions. Shared notes now use the exact recorded audience segment, covering joined groups, user-in-channel, admin and Echo-system contexts through their existing group routing. They never select a participant's private notes. A membership revision creates a distinct segment and does not silently copy previous notes to the new audience.

The scratchpad tool is advertised in authorized shared contexts. Dispatch retains frozen tool authority, and the store resolves its scope from the initiating run. Reads recheck authority before returning; edits recheck under the SQLite writer transaction. Existing append-only revisions, compare-and-swap edits, deletion tombstones and complete cursor listing remain intact. No schema migration or historical record rewrite is required. The legacy payload key `principal` holds the internal storage scope; clients cannot supply it.

Native regression `tests/security/test_silo_scratchpad.ep` exercises actual streamed tool selection, request recording and dispatch, member reads, private and channel isolation, reopen, removal denial and new-audience separation. The existing private continuity test passes cross-session notes, edits, deletion, conflicts and outsider denial. These tests use deterministic provider responses; they do not claim a new live-model behavioral evaluation. Evidence: evidence/phase2/silo-scratchpad-20261016/.
