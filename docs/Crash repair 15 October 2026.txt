Crash repair — 15 October 2026

The repeated native server crash was reproduced, not inferred from the gateway error. AddressSanitizer showed use-after-free during concurrent request processing: temporary list and string values were collected before their callers retained them, and a collector read a list backing buffer while another thread resized it. The latter failure reproduced after the temporary-value repairs, proving those repairs alone were insufficient.

Echo now runs a single listener owner, a fresh native process for each HTTP connection, and a separate native process for each model worker. The request process exits after sending its response. The listener and request processors do not share mutable Ernos heaps. Model worker claims, archive ownership checks, cancellation and recovery locks remain durable. posix_spawn passes explicit argument arrays and the existing host environment, without a shell. Only standard output/error and the selected connection descriptor are inherited; model processes inherit no request socket or listener. Worker launch failures are recorded as launch-failed instead of silently remaining running.

The implementation is in app/server.ep, app/transport/isolated_process.ep and app/web/{routes,recovery,worker}.ep. Application list values now have named retention where needed; app/retained_text.ep reads strings from caller-retained lists without allocating an unrooted duplicate. Ernos compiler/runtime sources were not changed for this repair. Sanitizer C was unmodified compiler output used only for diagnosis.

Acceptance evidence:
- crash-isolated-read-stress.log: 1,200 authenticated trace/transcript/status requests, 12 overlapping requests at a time, passed on the sanitizer build. No AddressSanitizer error in crash-roots-asan-5.log.
- crash-isolated-chat-speech.log: two fresh local MLX chats completed during concurrent reads; both saved responses synthesized through local Kokoro.
- crash-fixed-native-stress.log: the normal native build passed the same 1,200-request workload.
- crash-regression-results.json: seven native Ernos regression programs passed: event archive, checkpoint, session context, provider registry, trace API, direct message speech and voice tool. Speech checks include foreign-device denial and idempotent reuse.
- crash-fixed-cancellation.json: an actively generating isolated model worker was cancelled through the authenticated API.
- Dynamic port startup with a minimal server profile returned HTTP 200 from its isolated request process.
- Live browser follow-up completed; its Thinking panel appeared above its response; Speak produced a playable inline WAV.
- The LAN HTTPS status endpoint responded with its configured local CA validated.

This repairs the reproduced shared-heap request crash. The tests are finite acceptance workloads, not an indefinite endurance claim. Model workers still use their existing internal cancellation-monitor threads; the compiler's general threading implementation was not changed or certified. Reliable reboot supervision remains the previously documented separate deployment item.

Earlier failed sanitizer attempts remain as evidence, including crash-roots-asan-4.log for the list-resize race. Raw gateway logs and runtime databases contain private data and credentials and must not be published.
