Echo foreground service startup — 15 October 2026

Authored implementation: app/start_service.ep and app/lifecycle/service_profile.ep.
These are host commands, not tools exposed to the model or remote devices.
Profiles contain explicit executable, working directory, argv and environment.
They are configuration data. Executable orchestration remains plain-English Ernos.

Build from the internal compiler directory using:
./epc '/Volumes/One Touch/Echo/app/start_service.ep'
Confirm Self-hosted compilation successful! in the compiler output.

Inspect each configured executable/working directory without starting it:
./start_service '/Volumes/One Touch/Echo/environments/mlx-service.json' check
./start_service '/Volumes/One Touch/Echo/environments/llama-service.json' check
./start_service '/Volumes/One Touch/Echo/environments/echo-service.json' check

Start a stopped service in the foreground by omitting check. The launcher replaces
itself with the service, preserving PID, signals and actual exit status. There is
no shell evaluation of profile strings and no automatic restart. Standard output
and standard error go to the caller; retain these in an evidence/runtime log.
Do not run a second service on an occupied port or interrupt an active run just
to adopt these profiles. Check validates the executable and working directory,
not model files, free ports, runtime health, dependencies or full acceptance.

The profiles record the current host paths and qualification settings. They are
not portable installation packages or a finished supervisor/start-stop-update UI.
The Echo profile references the current internal database and generated sidebar
asset. Updating the deployment requires updating that profile deliberately.
The existing database's registered default remains authoritative.

MLX cache must point at the existing internal hf-cache. Without it, the upstream
/v1/models handler can fail even though /health succeeds. Offline flags prevent
implicit acquisition, not a completed network-blocked offline acceptance claim.
The MLX adapter explicitly supplies remaining context as max_completion_tokens
on each request; upstream server's fallback generation default is not Echo's
request budget. The llama profile requests model context and disables its
configurable prediction ceiling. One llama slot is the measured qualification
configuration, pending full-context concurrency scheduling qualification.

Current tests exercise actual exec, argv containing shell-looking text and spaces,
environment replacement, cwd and exit status. Complete lifecycle acceptance still
requires live launches of these provider profiles, shutdown/reboot, dependency
locking, health supervision, log management and verified storage persistence.
